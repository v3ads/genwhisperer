# GenWhisperer Template: eStage Runtime Safeguards

## Purpose

`estageRuntimeSafeguards.ts` is a framework-neutral TypeScript template for code generated by GenWhisperer inside eStage projects. It prevents optional eStage runtime APIs from becoming uncaught browser errors, while preserving the platform’s security model: no provider API keys or connector secrets are placed in the client bundle.

## What the Template Provides

| Component | Purpose |
|---|---|
| `CapabilityResult<T>` | A stable result union that separates a successful call from `UNAVAILABLE`, `OFFLINE`, and `FAILED` conditions. |
| `invokeEstageCapability` | Shared invocation wrapper for availability checks, safe telemetry, error sanitization, and retry boundaries. |
| `summarizeWithEstageAI` | Example of a credit-consuming AI action with no automatic retry. |
| `loadCommunityThreads` | Example of an idempotent read with one bounded retry for a transient network interruption. |
| `trackFunnelEvent` | Example of best-effort analytics that cannot block a successful primary user action. |
| Minimal `Window` declarations | Project-scoped types that can be expanded only for the runtime methods the generated app actually uses. |

## Generator Rules

GenWhisperer should copy the template into a generated project only when the project needs an eStage runtime integration. It should then retain the generic wrapper, add the smallest necessary `Window` type declarations, and create task-specific wrappers rather than calling a global directly from a UI component.

The generator must assign an action one of two retry classes. **Idempotent reads** may use `retryMode: "idempotent-read"`; examples include loading a blog snapshot or a community feed. **Side effects** must use `retryMode: "never"`; this includes AI actions that spend project credits, connector sends, uploads, lead capture, posts, comments, and all actions that can create an external record or notification.

Every generated caller must show an inline unavailable or failure state based on the result code. It must not use optional chaining alone when a visitor expects an outcome.

## Type Validation

The standalone template was validated successfully with:

```bash
pnpm exec tsc --noEmit --target ES2022 --module NodeNext --moduleResolution NodeNext --strict --lib DOM,ES2022 templates/estageRuntimeSafeguards.ts
```

## Adaptation Example

A generated support-chat component should not write `window.estageAI?.chat(...)` inline. It should expose a wrapper that checks `window.estageAI?.chat`, returns `UNAVAILABLE` if the project AI feature is off, does not automatically retry a potentially credit-consuming call, and renders a human-readable setup or availability message.

A generated connector notification button should disable while the action is in flight, preserve the user’s form state on failure, and require an explicit user retry. It must never inject an API key into site code.
